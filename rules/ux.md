# UI/UX Guidelines (based on ISO 9241-110 / CPUX-F)

For every change to user interfaces:

- Error messages say what went wrong and how the user can fix it. No technical
  codes alone.
- Every action that processes something or changes state shows visible feedback
  (loading state, success, error).
- Destructive actions can preferably be undone. Only irreversible actions
  require confirmation, and the dialog names the consequence.
- Form fields have visible labels, required fields are marked, and input is
  preserved when errors occur.
- Everything is operable by keyboard; focus is visible.
- The UI uses the users' domain terms from the domain model, not technical
  terms. Identical things are named and behave identically everywhere (terms,
  button placement).
